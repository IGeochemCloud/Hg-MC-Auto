# Evaluation 实时监控可行性与实现路线

## 结论

**可以做插件，但目前能确认的只是 GUI 驱动的批量导出，不是 Evaluation 的实时数据接口。** 现有 MC-ICP-MS 软件配置是基于固定屏幕坐标、鼠标/键盘/剪贴板动作的 RPA 配置。它可以批量触发导出，但窗口缩放、布局、软件版本或弹窗变化都会影响可靠性；该配置本身没有 OCR、屏幕目标识别或数据流订阅。

因此应分开定义两种能力：

1. **近实时结果监测（推荐先做）**：Evaluation/导出流程生成文件后，监测文件变化、确认写入完成、解析结果并生成 QC packet。
2. **屏幕观察（可选降级能力）**：只读截屏，从可见数值/状态提取候选值；显示来源、置信度和时间戳，必须允许人工核对。它不能被当作原始测量数据的权威来源。

若用户要求在采集过程中实时监控，而 Evaluation 没有持续落盘文件、日志、数据库/API 或可访问性接口，则屏幕识别可能是唯一可探索路线，但必须用实际 Evaluation 版本、屏幕分辨率、DPI、语言、页面状态和仪器数据验证，不应仅凭当前坐标配置承诺可用。

## 当前实现基线

- 软件配置文件：`software_profiles/MC-ICP-MS.json`
- 配置标题：`Data Evaluation`，配置版本：`3.2.0.0`
- 动作按固定坐标点击，并用键盘/剪贴板填写输入与输出路径。
- 旧导出脚本曾在 GUI 动作完成后直接返回成功，不核实输出文件。
- 当前已增加输出后置条件：目标文件必须存在、非空且连续采样稳定后才报告成功。该检查只是导出可靠性检查，不等于 Evaluation 实时接口。

## 建议按优先级探测数据源

1. **Evaluation 导出目录/自动保存目录**：监听新文件或稳定写入，改动最小，优先采用。
2. **Evaluation 日志、SQLite/本地数据库、命令行或厂商 API**：如果厂商支持，这是更好的权威来源；先确认格式、锁和许可限制，只读接入。
3. **Windows UI Automation / Accessibility**：比像素坐标稳定，可读取控件名、表格单元格和状态，但需要实机检查 Evaluation 控件是否暴露语义信息。
4. **图像模板识别与 OCR**：仅作 fallback。OCR 结果需要范围/单位校验、连续帧去抖、检测置信度和人工复核；界面截图不得自动变成已验证的实验结果。

## 安全边界

- 监控插件默认只读，不点击“开始/停止测量”、不调整杯位/增益/质量偏移等仪器参数。
- UI 自动化期间要求锁定会话、检查正确窗口标题和软件版本；出现未知弹窗、窗口失焦或置信度不足时立即暂停并提示人工。
- 不允许 OCR 误读结果被直接用于仪器控制或自动剔除样品。
- 每条记录保存源文件/来源控件、观测时间、解析版本、质量标记、人工复核状态；不得覆盖原始文件。
- 实验室验证阶段在仿真/历史数据上对比屏幕读取与 Evaluation 导出值，并记录误读、漏读和延迟。

## 建议 MVP

**阶段 A：可靠的落盘监测**

- 由操作者正常完成一次导出。
- 等待导出文件完成写入后解析 CSV/XLSX，生成带来源的 `qc.v1`。
- 用已有 monitor 监视结果目录，可选异步 LLM 解读；任何结论保持待人工确认。

**阶段 B：Evaluation 可访问性探测器**

- 只读取活动窗口标题、控件树、可访问文本和屏幕截图，不发送鼠标/键盘输入。
- 对照人工选定的 3–5 个可见指标验证控件可读性和单位。
- 若控件树不可用，再做独立 OCR adapter 原型。

**阶段 C：实时观察插件**

- 只有经过实验室验证并具有可重复读取的数据源时才发布。
- 以 `ObservationSource` 接口区分文件观察、UIA 观察和 OCR 观察；后两者必须声明 `source_kind`、`confidence` 和 `human_review_required`。
- 默认只做通知、图表和建议，不做闭环仪器控制。

## 需要实机验证的信息

开始 UIA/OCR 原型前，需确认：Evaluation 完整版本号、操作系统/分辨率/DPI、实时页面截图（可打码）、是否能在采集过程中保存 CSV/XLSX、是否生成日志/数据库文件、哪些字段需要实时观察，以及允许的采样频率。屏幕截图和数据文件应去除样品/患者/商业敏感标识后再用于调试。
